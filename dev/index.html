MatrixProductToolbox.jl

Matrix-product states and operators for closed and open quantum systems, built around three goals:

  • Simplicity. Six tensor contractions are the entire compute core. Everything else — norms, overlaps, expectation values, operator application — is built from them.
  • Flexibility. One generic container, MatrixProduct, parametrised by the number N of physical legs per site. N = 1 is a state, N = 2 an operator, and open-system objects need no new types.
  • Platform agnosticism. Site tensors are plain AbstractArrays, so Array, CuArray and Reactant/XLA arrays all work through the same code path. The package has no platform-specific dependencies and no backend hooks.

Installation

using Pkg
Pkg.add("MatrixProductToolbox")

A first look

using MatrixProductToolbox
using LinearAlgebra
using Random

ψ = rand_mps(ComplexF64, fill(2, 6); maxdim = 8, rng = MersenneTwister(0))
MPS{ComplexF64}(L=6, d=[2, 2, 2, 2, 2, 2], χ=[1, 2, 4, 8, 4, 2, 1], center=1:1)

Bond dimensions are capped from both ends by the local Hilbert spaces, so maxdim = 8 is reached only in the middle of the chain:

bond_dims(ψ)
7-element Vector{Int64}:
 1
 2
 4
 8
 4
 2
 1

rand_mps returns a normalised, right-canonical state. Moving the orthogonality centre is an exact gauge transformation — it changes the tensors but not the state:

canonicalize!(ψ, 3)
center(ψ), norm(ψ)
(3:3, 0.9999999999999992)
isleftorthogonal(ψ[1]), isrightorthogonal(ψ[6])
(true, true)

Measure a local operator on every site:

σz = ComplexF64[1 0; 0 -1]
round.(real(expect(σz, ψ)); digits = 4)
6-element Vector{Float64}:
 -0.1051
 -0.2868
  0.1954
 -0.3301
 -0.0723
  0.2698

Compress the state, and see what it cost:

φ = truncate(ψ; maxdim = 3)
bond_dims(φ), round(abs(dot(φ, ψ))^2; digits = 6)
([1, 2, 3, 3, 3, 2, 1], 0.94658)

Index conventions

Every site tensor has the index order

A[l, p₁, …, p_N, r]

— left bond first, physical legs in the middle, right bond last. Boundary bonds keep dimension 1 rather than being dropped, so every tensor has exactly N + 2 indices and no routine needs a special case for the ends of the chain.

Index orderMeaning
MPSA[a, s, a′]left bond, physical, right bond
MPOW[w, s′, s, w′]left bond, output physical, input physical, right bond

For an MPO, W[w, s′, s, w′] = ⟨s′|Ŵ|s⟩: the bra contracts with s′ and the ket with s.

This ordering is chosen so that both canonicalization reshapes are contiguous — reshape(A, l * ∏p, r) going left to right and reshape(A, l, ∏p * r) going right to left — so gauging a matrix-product object needs no permutedims at all.

What is not here yet

DMRG and TDVP are not implemented. The pieces they need — the effective-operator kernels and their index conventions — are in place and tested, so those algorithms will be additive rather than a redesign. See apply_effective.
