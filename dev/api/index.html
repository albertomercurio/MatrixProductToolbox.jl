Types

MatrixProductToolbox.AbstractMatrixProduct — Type
abstract type AbstractMatrixProduct{N}

Supertype for one-dimensional matrix-product objects, where N is the number of physical legs carried by every site.

A matrix-product object is a chain of L site tensors, each with the index order

A[l, p₁, …, p_N, r]

where l is the left bond, p₁ … p_N are the physical legs and r is the right bond. Boundary bonds have dimension 1 rather than being omitted, so every site tensor has exactly N + 2 indices and all generic code is shape-agnostic.

N = 1 is a matrix-product state (MPS) and N = 2 is a matrix-product operator (MPO). Larger N is allowed but has no dedicated support.

Notes

  • This is a strictly one-dimensional container: every site has exactly one left and one right bond. Generic tensor networks with arbitrary connectivity are out of scope.
  • N varies the number of physical legs per site, never the connectivity.

Interface

A concrete subtype T <: AbstractMatrixProduct{N} must implement

  • Base.length(::T): the number of sites.
  • Base.getindex(::T, i::Integer): the site tensor at site i.
  • center(::T): the orthogonality centre as a UnitRange{Int}.
  • MatrixProductToolbox.setsite!(::T, i::Integer, t): replace a site tensor without touching the gauge label.
  • MatrixProductToolbox.setcenter!(::T, r::UnitRange{Int}): set the gauge label.

Everything else (physical_dims, bond_dims, canonicalize!, expect, …) is generic and follows from these five.

MatrixProductToolbox.MatrixProduct — Type

    tensors::Vector{A}
    center::UnitRange{Int}
end

A one-dimensional chain of site tensors with N physical legs each.

Each site tensor has the index order A[l, p₁, …, p_N, r]; see AbstractMatrixProduct for the full convention. The two aliases

const MPS = MatrixProduct{1}    # A[a, s, a′]
const MPO = MatrixProduct{2}    # W[w, s′, s, w′]

are distinct types.

Fields (Attributes)

  • tensors::Vector{A}: the L site tensors, each with N + 2 indices.
  • center::UnitRange{Int}: the orthogonality centre; see center.

Constructors

MatrixProduct(tensors, center = 1:length(tensors))
MatrixProduct{N}(tensors, center = 1:length(tensors))

N is inferred from ndims of the site tensors when omitted. center may also be given as an Integer, which is interpreted as the single-site range c:c. The constructor validates that every tensor has N + 2 indices, that neighbouring bonds match, that both boundary bonds have dimension 1, and that center lies within 1:L.

No implicit canonicalization

Construction never gauges or otherwise modifies the tensors you pass in. A fresh object therefore has center == 1:L, which claims nothing. Call canonicalize! to establish a gauge.

Examples

julia> ψ = MPS([reshape([1.0, 0.0], 1, 2, 1), reshape([0.0, 1.0], 1, 2, 1)])
MPS{Float64}(L=2, d=[2, 2], χ=[1, 1, 1], center=1:2)

julia> bond_dims(ψ)
3-element Vector{Int64}:
 1
 1
 1

MatrixProductToolbox.MPO — Type
const MPO = MatrixProduct{2}

A matrix-product operator: two physical legs per site, with site tensors indexed W[w, s′, s, w′] (left bond, output physical, input physical, right bond), so that $W[w, s', s, w'] = \langle s' | \hat{W} | s \rangle$.

The bra contracts with the output leg s′ and the ket with the input leg s.

An MPO also serves as a density matrix in matrix-product form, which is why open quantum systems need no additional types.

Examples

julia> W = MPO([reshape(ComplexF64[1 0; 0 -1], 1, 2, 2, 1)])
MPO{ComplexF64}(L=1, d=[(2, 2)], χ=[1, 1], center=1:1)

julia> physical_dims(W)
1-element Vector{Tuple{Int64, Int64}}:
 (2, 2)

MatrixProductToolbox.product_mps — Function
product_mps([T,] states)

A MPS representing an unentangled product state, with all bonds of dimension 1.

The first form takes the local state vectors directly. The second builds the computational basis state $|i_1 i_2 \ldots i_L\rangle$ from a list of local dimensions and one-based indices.

MatrixProductToolbox.center — Function
center(ψ)

The orthogonality centre of ψ: the range of sites not known to be orthogonal.

The invariant is that sites 1:first(center(ψ))-1 are left-orthogonal and sites last(center(ψ))+1:end are right-orthogonal. Every value is meaningful, so there is no "unknown" sentinel:

ValueMeaning
1:Lnothing claimed — e.g. a freshly constructed object
c:cmixed-canonical with the centre at site c
1:1right-canonical
L:Lleft-canonical
i:i+1a two-site block

Arguments

  • ψ: an AbstractMatrixProduct.

Returns

  • r::UnitRange{Int}: the orthogonality centre.

Examples

julia> ψ = rand_mps(ComplexF64, [2, 2, 2, 2]; maxdim = 4);

julia> center(ψ)
1:1

julia> center(canonicalize!(ψ, 3))

Canonical forms and truncation

MatrixProductToolbox.canonicalize! — Function
canonicalize!(ψ, c = 1; trunc = NoTruncation(), factorization = SVDFactorization())

Move the orthogonality centre of ψ to site c, in place.

Afterwards sites 1:c-1 are left-orthogonal, sites c+1:end are right-orthogonal, site c carries the norm, and center(ψ) == c:c. With the default trunc this is an exact gauge transformation: it leaves the represented state untouched.

Arguments

  • ψ: the matrix-product object to gauge.
  • c: the target site for the orthogonality centre.
  • trunc: an AbstractTruncation policy. Only bonds the sweep crosses are affected, so use truncate! to truncate every bond.
  • factorization: an AbstractFactorization.

Notes

  • Only the bonds between the current centre and c are touched, so repeatedly moving the centre one site at a time costs one factorization per step.
  • A freshly constructed object has center == 1:L, so the first call sweeps the whole chain.

Returns

  • ψ: the same object, mutated.

Examples

julia> ψ = rand_mps(ComplexF64, [2, 2, 2, 2]; maxdim = 4);

julia> canonicalize!(ψ, 3);

julia> center(ψ)
3:3

julia> isleftorthogonal(ψ[1]) && isrightorthogonal(ψ[4])
true
source

MatrixProductToolbox.truncate! — Function
truncate!(ψ; maxdim, cutoff, trunc, to = 1, factorization = SVDFactorization())

Truncate every bond of ψ, in place.

Sweeps first to the last site to establish a gauge, then back to the first site applying trunc at each bond, and finally moves the centre to to. The two-pass structure is what makes the truncation optimal: each discarded singular value is the true Schmidt coefficient of the bond.

Arguments

  • ψ: the matrix-product object to truncate.
  • maxdim: convenience shorthand for Truncation(; maxdim).
  • cutoff: convenience shorthand for Truncation(; cutoff).
  • trunc: an AbstractTruncation. Defaults to Truncation(maxdim, cutoff); pass FixedTruncation explicitly for a Reactant-compatible sweep.
  • to: the site where the orthogonality centre is left.
  • factorization: an AbstractFactorization.

Notes

  • Truncation is not a gauge transformation: it changes the represented state unless every discarded singular value is zero.

Returns

  • ψ: the same object, mutated.

Examples

julia> ψ = rand_mps(ComplexF64, [2, 2, 2, 2, 2, 2]; maxdim = 8);

julia> bond_dims(ψ)
7-element Vector{Int64}:
 1
 2
 4
 8
 4
 2
 1

julia> bond_dims(truncate!(ψ; maxdim = 3))
7-element Vector{Int64}:
 1
 2
 3
 3
 3
 2
 1

Truncation policies

MatrixProductToolbox.AbstractTruncation — Type
abstract type AbstractTruncation

Supertype for bond-truncation policies.

A policy answers one question: given the singular values of a bond matrix, how many of them are kept? The distinction that matters is what the answer depends on:

PolicyRank ruleDepends onArray / CuArrayReactant / XLA
NoTruncationk = min(m, n)shape✅✅
FixedTruncationk = min(maxdim, m, n)shape✅✅
Truncationsmallest k meeting cutoffsingular-value magnitudes✅❌

XLA requires every array shape to be known at trace time. It does not require uniform bond dimensions — only that they be a function of shapes alone. That is exactly the top two rows, which is why they are traceable and Truncation is not.

source
MatrixProductToolbox.NoTruncation — Type
struct NoTruncation <: AbstractTruncation

Keep the full rank min(m, n) of every bond matrix; the factorization is exact.

This is the default for canonicalize!, which is a pure gauge transformation.

source
MatrixProductToolbox.Truncation — Type
struct Truncation{T<:Real} <: AbstractTruncation
    maxdim::Int
    cutoff::T
end

Truncation(; maxdim = typemax(Int), cutoff = 0.0)

Discard singular values based on their magnitude.

Keeps the smallest k ≤ maxdim such that the relative discarded weight

\[\varepsilon = \frac{\sum_{i > k} \sigma_i^2}{\sum_i \sigma_i^2}\]

does not exceed cutoff. Bond dimensions therefore adapt to the state, which is what you usually want on Array and CuArray.

Not traceable

Because k depends on the singular values themselves, the output shape is a runtime value. This cannot be used inside a Reactant @compile region — use FixedTruncation there.

Fields (Attributes)

  • maxdim::Int: hard cap on the kept bond dimension.
  • cutoff::T: maximum tolerated relative discarded weight.
source
MatrixProductToolbox.FixedTruncation — Type
struct FixedTruncation <: AbstractTruncation
    maxdim::Int
end

Keep k = min(maxdim, m, n) singular values, decided by the bond matrix shape alone.

Not a uniform bond dimension

Near the ends of the chain min(m, n) < maxdim, so bonds there are genuinely smaller — but deterministically, from the chain geometry. That is precisely what XLA needs, and it means no zero-padding is ever required, so the resulting isometries are exact.

Fields (Attributes)

  • maxdim::Int: the target bond dimension, reached wherever the geometry allows.

Factorizations

MatrixProductToolbox.AbstractFactorization — Type
abstract type AbstractFactorization

Supertype for the matrix factorization used to move the orthogonality centre.

A factorization splits a bond matrix into an isometry and a remainder. Only SVDFactorization is currently implemented; the abstract type exists so that alternatives (a QR for untruncated sweeps, or a Cholesky-QR on backends with cholesky but no qr) can be added without touching any algorithm.

Interface

factorize_left(alg, trunc, M)  -> (Q, R, info)   # Q'Q ≈ I, M ≈ Q * R
factorize_right(alg, trunc, M) -> (L, Q, info)   # QQ' ≈ I, M ≈ L * Q
source

Factorize via the singular value decomposition.

Works on every supported backend and is the only factorization that can truncate. This is the default everywhere.

MatrixProductToolbox.apply_effective — Function
apply_effective(L, W, x, R)

Apply the one-site effective operator to a site tensor.

Contracts

\[y[b, s', b'] = \sum_{a, w, s, w', a'} L[b, w, a] \, W[w, s', s, w'] \, x[a, s, a'] \, R[b', w', a']\]

with L the environment left of the site and R the environment right of it. The result carries the same index order as a site tensor, so it can be fed straight back into a matrix-product object.

This is the linear map that DMRG diagonalises and that TDVP exponentiates. It is provided now so that the effective-operator index conventions are fixed and tested; the environment cache that feeds it arrives with those algorithms.

Arguments

  • L: the left environment, indexed [b, w, a].
  • W: the MPO site tensor, indexed [w, s′, s, w′].
  • x: the site tensor to act on, indexed [a, s, a′].
  • R: the right environment, indexed [b′, w′, a′].

Returns

  • y: the result, indexed [b, s′, b′].

MatrixProductToolbox.apply — Function
apply(H, ψ; trunc = NoTruncation(), to = 1, factorization = SVDFactorization())

Apply the MPO H to the MPS ψ.

Each pair of site tensors is contracted over the physical index and the MPO and MPS bonds are fused, so the bond dimensions multiply: a state of bond dimension χ acted on by an operator of bond dimension D comes back with bond dimension χD. Pass trunc to compress the result in the same call.

Arguments

  • H: an MPO with the same number of sites as ψ.
  • ψ: an MPS.
  • trunc: an AbstractTruncation. The default leaves the result exact; pass e.g. Truncation(; maxdim = 32) to compress, or FixedTruncation for a Reactant-compatible sweep.
  • to: where to leave the orthogonality centre, when truncating.
  • factorization: an AbstractFactorization, when truncating.

Notes

  • Without truncation the result is exact but its bond dimension grows, so applying an operator repeatedly needs a trunc.

Returns

  • φ::MPS: the state H|ψ⟩.

Examples

julia> ψ = rand_mps(ComplexF64, fill(2, 4); maxdim = 4);

julia> σx = ComplexF64[0 1; 1 0]; H = product_mpo([σx, σx, σx, σx]);

julia> dense(apply(H, ψ)) ≈ dense(H) * dense(ψ)
true

Dense representation

MatrixProductToolbox.dense — Function
dense(ψ; maxsize = 2^24)

Contract a matrix-product object into its full dense representation.

An MPS becomes a state vector of length prod(physical_dims(ψ)); an MPO becomes a matrix. The result stays on the same array backend as the input — use Array(ψ) to bring it to the host.

Arguments

  • ψ: an MPS or MPO.
  • maxsize: refuse to allocate more than this many entries, as a guard against accidentally contracting a large chain.

Notes

  • Site 1 is the fastest-varying index, so reshape(dense(ψ), physical_dims(ψ)...) has dimension i equal to site i. This is the opposite of kron's ordering: build a reference operator as reduce(kron, reverse(ops)) to compare.
  • The cost is exponential in the number of sites. This is a testing and teaching tool.

Returns

  • v: a Vector for an MPS, a Matrix for an MPO.

Examples

julia> ψ = product_mps([2, 2], [1, 2]);

julia> round.(real(dense(ψ)); digits = 12)
4-element Vector{Float64}:
 0.0
 0.0
 1.0
 0.0
